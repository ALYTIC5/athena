<Chunk n={1} title="Exceptions: raise, catch and clean up">

An **exception** is an object raised when something goes wrong. It travels up through the calling functions until a `try`/`except` catches it, or the program stops with a traceback. Exceptions form a hierarchy (`ValueError` and `KeyError` are kinds of `Exception`). Catch the most specific type you can handle, and never a bare `except:`.

In a `try` statement, `except` handles a matching exception, `else` runs only if nothing was raised, and `finally` always runs, even on a `return`. Use `raise` to signal a problem, and `raise NewError(...) from error` to keep the original as the cause. Inside an `except` block, a bare `raise` re-raises the exception being handled. A new exception type needs only a `class` line, as below.

**EAFP** (easier to ask forgiveness than permission) means trying the action and handling the failure. **LBYL** (look before you leap) means checking first. EAFP is often safer, because the situation can change between the check and the action.

**Worked example.** Booking a slot, with a custom exception.

```python
class SlotTakenError(Exception):
    """Raised when a slot is already booked."""

def book(slots, slot):
    if slot in slots:
        raise SlotTakenError(slot)       # raise a specific error
    slots.add(slot)

slots = set()
for wanted in ["09:00", "09:00"]:
    try:
        book(slots, wanted)
    except SlotTakenError as error:      # catch only this problem
        print("taken:", error)
    else:
        print("booked", wanted)          # runs only if nothing was raised
    finally:
        print("checked", wanted)         # always runs
```

The same idea in both styles.

```python
record = {"hour": "9"}
# LBYL: check first
hour = int(record["hour"]) if "hour" in record and record["hour"].isdigit() else None
# EAFP: try it, and handle the failure
try:
    hour = int(record["hour"])
except (KeyError, ValueError):
    hour = None
print(hour)   # 9
```

<Callout type="note" title="Retrying temporary failures">

A **retry decorator** wraps a call in a loop. It catches only a tuple of listed, temporary exceptions such as a timeout, and it re-raises the last one after `max_attempts` calls in total. You will write one in the mastery check. Only retry calls that are safe to repeat.

</Callout>

<Callout type="misconception" title="Common misconceptions in chunk 1">

- "`except Exception: pass` makes the program safe." It hides real bugs, so failures go unnoticed.
- "`finally` only runs when there was an error." It runs every time, including after a `return`.
- "Handlers are matched by best fit." The first matching `except` runs, so put the specific one first.

<Chunk n={2} title="Context managers, files, JSON and CSV">

A `with` statement runs setup and guarantees cleanup, even if the block raises: `with open(path) as f:` closes the file at the end. A **context manager** is an object that does this. The short way to write one is a generator function with `@contextlib.contextmanager`. Code before `yield` is setup, the `with` body runs at the `yield`, and code after it, inside a `finally`, is cleanup.

`pathlib.Path` represents a file path: `Path(folder) / "bookings.json"`, with `.read_text()` and `.write_text()`. `json.dumps` and `json.loads` convert between Python values and JSON text, and JSON objects become dicts whose keys are always strings. `csv.DictReader` gives each row as a dict of strings, so convert numbers yourself. Bad JSON raises `json.JSONDecodeError`, a kind of `ValueError`.

**Worked example.** Write and read JSON with a context manager around the write.

```python
import contextlib
import json
import tempfile
from pathlib import Path

@contextlib.contextmanager
def announce(label):
    print("start", label)
    try:
        yield                          # the body of the with block runs here
    finally:
        print("end", label)            # runs even if the body raises

with tempfile.TemporaryDirectory() as folder:   # a throwaway folder, deleted after the block
    path = Path(folder) / "bookings.json"
    with announce("write"):
        path.write_text(json.dumps([{"id": "b1", "hour": 9}]))
    data = json.loads(path.read_text())
    print(data[0]["hour"])             # 9: numbers survive, keys are strings
```

CSV text becomes dicts of strings.

```python
import csv
import io

text = "id,caller\nb1,amara\nb2,bayu\n"
rows = list(csv.DictReader(io.StringIO(text)))   # StringIO makes text act like a file
print(rows[1]["caller"], type(rows[0]["id"]).__name__)   # bayu str
```

<Callout type="misconception" title="Common misconceptions in chunk 2">

- "JSON keeps my dict keys as they were." Keys always become strings, so `{9: "free"}` comes back as `{"9": "free"}`.
- "CSV numbers come back as numbers." Every CSV value is a string until you convert it.
- "A context manager always hides exceptions." By default it only runs the cleanup, and the exception carries on. In a generator-based one the exception is raised at the `yield`, and a `try`/`except` around the `yield` can catch and suppress it.

<Chunk n={3} title="Dates, times and time zones">

A **naive** datetime is a clock reading with no time zone. An **aware** datetime has a UTC offset and stands for a moment in time. Ordering comparisons such as `<` between a naive and an aware one raise `TypeError`, and two naive times from different cities compare wrongly. So store and compare times in UTC, and convert to a local zone only to show them.

**ISO 8601** is the standard text form, such as `2026-11-02T09:00:00+00:00`. `fromisoformat` reads it and `isoformat()` writes it. `ZoneInfo("Europe/London")` is a named time zone that follows daylight saving. `dt.replace(tzinfo=zone)` attaches a zone to a reading that is already local to it, and `dt.astimezone(zone)` converts an aware time to another zone.

**Worked example.** The same moment in two zones, and the naive trap. This block uses a fixed offset, because a named zone needs the tz database.

```python
from datetime import datetime, timedelta, timezone

utc = datetime(2026, 11, 2, 14, 0, tzinfo=timezone.utc)      # aware: it knows its offset
tokyo = timezone(timedelta(hours=9))                         # a fixed offset, not a named zone
print(utc.astimezone(tokyo).isoformat())                     # 2026-11-02T23:00:00+09:00
print(utc == utc.astimezone(tokyo))                          # True: the same moment
try:
    datetime(2026, 11, 2, 14, 0) < utc                       # naive against aware
except TypeError:
    print("cannot compare naive and aware")
```

A named zone, as you will use it in the exercises:

```python nocheck="needs the tzdata package"
from datetime import datetime, timezone
from zoneinfo import ZoneInfo

local = datetime(2026, 11, 2, 9, 0).replace(tzinfo=ZoneInfo("America/New_York"))
print(local.astimezone(timezone.utc).isoformat())    # 2026-11-02T14:00:00+00:00
```

<Callout type="note" title="Keep the clock out of your logic">

Code that calls `datetime.now(timezone.utc)` inside a function gives a different answer every time, which makes it hard to test. Take `now` as a parameter instead, and pass a fixed moment in tests.

</Callout>

<Callout type="misconception" title="Common misconceptions in chunk 3">

- "A naive datetime is UTC." It has no zone at all, so it means nothing until you say which zone it is in.
- "`astimezone` on a naive time is an error, or treats it as UTC." It silently assumes the computer's own zone, so the result depends on where the code runs. Attach a zone with `replace` first.
