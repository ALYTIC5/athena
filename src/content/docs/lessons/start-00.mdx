## Why this matters

Interviews for the roles you are targeting test code you write without help, and 59% of postings list English communication as a requirement. Athena is built around both: you write code unaided, and you learn to explain your thinking out loud. This short lesson shows you every kind of question first, on a topic so small that you can focus on the interface, and sets up the habits that protect your progress.

## Objectives

By the end of this lesson you can:

1. Use every kind of question and exercise in Athena.
2. Set a start date and find your weekly plan on Home.
3. Export your progress and explain why Safari can delete it.
4. Explain the AI rule: Claude is your tutor, not your author.
5. Describe the think-aloud approach in seven steps.

You can read simple Python at the level of this lesson's examples. Each exercise prompt explains what you need.

This lesson has no warm-up, no mastery check and no cards. Nothing here is graded for mastery, so use it to try things and make mistakes.

<Chunk n={1} title="Questions that make you commit first">

Most lessons check you with short questions. You answer first and read the explanation second, because working something out helps it stick better than re-reading.

Before you submit a graded question or a prediction, you pick how sure you are: guessing, unsure, fairly sure or certain. The level is recorded with your answer. Being sure and wrong tells you more than being unsure and wrong.

A **predict** item shows a few lines of Python. You type the output you expect, pick your confidence and press Submit answer.

Then **Run it** shows what really happens, and one or two "investigate" questions give you something to think about. The code runs in your browser, and nothing you type is sent anywhere.

**Worked example.** `//` is whole-number division and `%` is the remainder. `print` with several values separates them with a space. `len(x)` counts the items in a list. A variable name cannot start with a digit or be a Python keyword such as `class`.

```python
print(7 // 2, 7 % 2)   # 3 1: two fits into seven 3 times, with 1 left over
```

Try three kinds of question: predict, multiple choice (choose all that apply) and short answer (type a value).

<Chunk n={2} title="Exercises: five ways to practise">

Python runs in your browser in Pyodide, and SQL runs in PGlite, a version of PostgreSQL that runs there too. The first run in a session takes a few seconds while the runtime loads.

Python exercises have **Run** (shows the output), **Run tests** (the visible tests), **Check** (all tests, including hidden ones), **Show hint** and **Reset**. In write-tests exercises, Run and Run tests are switched off, because your tests must be tried on several versions of the code. Hidden tests show only their name and a message about the likely mistake, never their code. SQL exercises have no hidden tests: Check compares your query's result with the expected one.

The five exercises are **faded** (fill the blanks), **debug** (fix a planted bug), **make** (write it from scratch), **write-tests** (write pytest tests that catch buggy versions) and **SQL** (write a query). Early lessons give more support. Later ones start with the problem.

**Hints and credit.** There are three hints: a question, then a strategy, then a near-solution with blanks. A pass with no help earns full credit, and each hint lowers it. The solution unlocks after a pass, or after three failed checks and all three hints. Only a full-credit pass counts as **unaided**, which is how Athena records that you did it yourself.

First, a Parsons problem and a spot-the-bug question. A Parsons problem gives you scrambled lines, and one of them is a distractor that does not belong. Press a line in Available lines to add it to your solution, put the needed lines in order and set the indentation. With the keyboard, Space picks a line up, the arrow keys move it, Tab and Shift+Tab change the indentation and Enter drops it.

<Chunk n={3} title="Your progress lives in this browser">

Athena has no accounts and no server. Your progress, answers and drafts are saved in your browser's storage on this device (localStorage and IndexedDB). That keeps your data private, but you must do two things.

First, set a **start date** in <a href={href('settings/')}>Settings</a>. It must be a Monday. Home counts weeks from it and shows that week's plan: lessons and lab work (up to 2.75 hours), a short review, one hour of Interview Gym and, from week 2, one hour of job search. If you fall behind, move the date later.

Second, **export your progress** regularly. A browser keeps site data on a best-effort basis. It can delete it when the device runs low on space, and you can delete it by clearing site data. Export creates `athena-progress-YYYY-MM-DD.json`, and Import brings it back. Keep exports in a synced or backed-up folder.

**Safari** is stricter. If you have not clicked or tapped on a site for seven days of Safari use, and cross-site tracking prevention is on, Safari deletes the data the site created with script. That is where Athena stores your progress. So:

- Use Chrome or Firefox for Athena if you can.
- Or add Athena to your Home Screen. Safari may be more likely to grant persistent storage to it, but that is not a promise.
- Either way, export regularly.

- "My progress is safe because it is on my own computer." The browser, not you, decides when site data is deleted. An export file is yours.

<Chunk n={4} title="Claude is your tutor, not your author">

Live coding interviews often ask you to write code without AI help, and you need to understand every line you ship. So Athena has one rule for exercises: **write it yourself.** Claude can be your tutor, but not your author.

Every code exercise has an "I'm stuck" button. It builds a prompt and opens Claude in a new tab, and you paste the prompt in. The prompt tells Claude not to write the solution and to ask you one question at a time. You write the fix. Using it caps that exercise's credit at 0.75.

After your main make exercise in most lessons, **explain-back** gives you a prompt that makes Claude act as an interviewer. It asks why your code works and what could go wrong. Explaining your own code shows you what you only half understand.

Later, the Interview Gym has **AI-assisted drills**. There, using AI is the point: you direct it, then check and fix what it produces. That is a separate skill, practised on purpose.

<Quiz lesson="start-00" chunk={4} />

<Callout type="misconception" title="Common misconceptions in chunk 4">

- "Using AI at all is cheating." Not here. The rule is about who writes the code in an unaided exercise, and Athena also trains you to use AI well.
- "If Claude explains it, I understand it." Reading an explanation feels like understanding. Writing the code yourself is how you find out.

</Callout>

</Chunk>

<Chunk n={5} title="The think-aloud approach">

In a coding interview, how you work counts as much as the answer. The approach has seven steps, and you say each one out loud:

1. **Clarify** the problem: the input, the limits, the odd cases.
2. **Examples:** work two or three by hand, including an empty or tiny input.
3. **Brute force:** describe the simplest solution that works, and what it costs.
4. **Optimise:** find something faster or simpler, and say the trade-off.
5. **Code** it.
6. **Test** it with your examples.
7. **Complexity:** say how time and memory grow with the input size, in Big-O terms such as O(n).

**Worked example.** *Return the longest call duration in a list of minutes.*

1. Clarify: the list can be empty, so return `None` then.
2. Examples: `[12, 45, 30]` gives `45`, `[7]` gives `7`, `[]` gives `None`.
3. Brute force: sort from largest to smallest and take the first item. It works, but sorting does more work than the question needs.
4. Optimise: walk the list once and remember the largest so far.
5. Code:

```python
def longest(durations):
    best = None                        # nothing seen yet
    for d in durations:
        if best is None or d > best:   # first item, or a bigger one
            best = d
    return best

print(longest([12, 45, 30]), longest([7]), longest([]))   # 45 7 None
```

6. Test: the three examples give `45`, `7` and `None`.
7. Complexity: one pass over n items is O(n) time, and two variables is O(1) extra memory.

You do not need to know Big-O yet. A later lesson teaches it. For now, practise saying the seven steps.

<Callout type="misconception" title="Common misconceptions in chunk 5">

- "Starting with the brute-force idea wastes time." It proves you understand the problem, and it gives you a correct answer to improve on.
- "The seven steps are a script to recite." They are a checklist for staying unstuck. Skip a step when the problem is trivial, but say that you are skipping it.

</Callout>
